# Проверенный комплект МАЭСТРО для Codex

Это комплект сайта, PHP-приёмника и MySQL для целевого российского размещения. Он НЕ подключён к действующему боту Amvera и НЕ активирует Яндекс/грант. Сеть контейнеров и секреты не используются приложением Анима Тактус.

## Что уже проверяется
`Maestro isolated runtime package`: отдельные тесты упаковщика и полный путь Nginx → PHP-FPM → MySQL на синтетической заявке. Проверяются закрытые исходники, недоступность кабинета без токена, сохранённая запись, повтор с тем же номером и отсутствие токена в ответах.

## Перед запуском на сервере
1. Установить реальное приложение/проект Amvera или Yandex, действующий тариф, лимиты гранта, остаток и дату активации. Не создавать платные ресурсы по предположению.
2. Проверить точный SHA исходников и успешные прогоны. Скачать артефакт или получить эту feature-ветку. Сверить SHA256SUMS.txt, если используется артефакт.
3. Сохранить резервную копию действующей конфигурации и БД. Не менять существующие bot webhook/polling. Не применять миграцию 002 на свежей v2-схеме.
4. Настроить свой HTTPS-домен и законные сведения об операторе/согласии. Пример maestro.example НЕ является рабочим адресом.
5. Создать четыре независимых случайных секрета вне Git и публичного каталога: db_password, db_root_password, admin_token, ip_pepper. От 32 до 256 символов, без переводов строк внутри. Родительский каталог закрыт для обычных пользователей; файлы доступны только сервисам, которым нужны. Не выводить секреты в чат/CI/команды с history. Секреты из CI никогда не переиспользовать.
6. Определить точную схему TLS reverse proxy. Настроить Nginx real_ip только для подтверждённого доверенного прокси. Не доверять произвольному X-Forwarded-For. До этого ограничитель может считать посетителей одной группой: публичный запуск запрещён без проверки двух отдельных клиентов и подделанного заголовка.

## Воспроизводимый запуск (выполняет Codex, не владелец)
Из корня проверенной рабочей копии/распакованного артефакта, где ещё нет `dist/maestro`:

```sh
export MAESTRO_ORIGIN='https://APPROVED-HOST'
export MAESTRO_SECRET_DIR='/absolute/private/secret-directory'
python3 tools/package_maestro.py --origin "$MAESTRO_ORIGIN"
docker compose -f infra/runtime/compose.yaml config --quiet
docker compose -f infra/runtime/compose.yaml up -d --build --wait --wait-timeout 180
```

Контейнер сайта слушает **только 127.0.0.1:8082**. Настроенный TLS-шлюз должен направлять `/maestro/` и `/api/leads` на этот адрес. Порты MySQL и PHP-FPM не публикуются. Нужен отдельный вход оператора/защищённая рабочая консоль для admin-токена; не помещать его в JS или localStorage. Свежая база создаётся только на пустом named volume, существующая не стирается.

После сборки зафиксировать digest использованных образов и точный SHA кода. Теги базовых образов сами по себе не являются неизменяемыми идентификаторами.

## Обязательная приёмка на реальном HTTPS-адресе
- Сайт и все статические ресурсы доступны; `/server`, `.env`, PHP, SQL, внутренние инструкции снаружи не отдаются.
- Тестовая заявка с согласием записывается один раз; повтор и конфликт работают. После перезагрузки контейнеров запись остаётся.
- Проверены доступ по токену, неверный токен, два разных клиентских IP за TLS-шлюзом и поддельный forwarding-заголовок.
- Подтверждено получение уведомления владельцем. В этом комплекте **уведомления ещё не реализованы**: связать с существующим Amvera-ботом, не считать саму запись в БД уведомлением.
- Есть срок хранения/удаление, резервное копирование и пробное восстановление в отдельную БД. Не выдавать наличие volume за backup.
- Ошибки и контактные поля не попадают в рекламную аналитику/публичные логи.

## Откат
Сохранить предыдущий образ и настройки до переключения. При ошибке вернуть маршрутизацию на прежний адрес/образ, не удаляя named volume и не выполняя `down -v`. Команда `down -v` есть только в одноразовом CI для уничтожения учебной БД: на production её не применять.

## Другие зависимости
LLM, личный голос, новая CRM и выплаты не входят в этот пакет. Доступ к существующему движку Amvera подключается через `integrations/site_channel.py` в полном репозитории после проверки стекa. Нельзя заменять действующего робота этим приёмником: у него другая функция.
