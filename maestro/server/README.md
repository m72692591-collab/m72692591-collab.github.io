# MAESTRO SALES BACKEND — приём заявок без платных API

## Статус (26.10.2026)

Код **разработан и размещён в черновой ветке**. Настоящий сервер и домен ещё не подключены; отправка заявок **по умолчанию выключена**. Сайт сейчас по-прежнему копирует заявку в буфер обмена, если оператор не настроил сервер. Нельзя публиковать заявление «заявки автоматически доставляются» до реального теста на своём хостинге.

### Состав

- `lead-api.php` — PHP 8.2+ с JSON API POST для создания обращения и GET для админ-списка.
- `lead_schema.sql` — MySQL таблица, индекс по дате и псевдонимизированному адресу IP.
- `leads-admin.html` — интерфейс владельца, показывает последние 50 заявок, требует серверный токен администратора.
- `../assets/maestro-leads.js` — усиление текущей формы (HTTPS-запрос к серверу, только после действия и согласия посетителя; при выключенном API оригинальная форма не меняется).

### Как устроено

1. Посетитель заполняет форму, явно даёт согласие.
2. JavaScript вызывает HTTPS endpoint только если в `maestro/index.html` заполнен метатег `maestro-lead-endpoint`.
3. PHP проверяет Origin, JSON, заполнение, тематику, согласие, ловушку для автоматических отправок, ограничение 5 заявок с одного псевдонимизированного IP за час.
4. SQL сохраняет данные в российскую базу данных.
5. Сервер возвращает статус 201 и референс только если запись БД подтвердилась.
6. Владелец открывает `leads-admin.html` на **том же российском хосте, что и API**, вводит токен и видит до 50 последних обращений. Админ токен не хранится в браузере после запроса.

**Не хватает**: настоящего хостинга/секретов, мониторинга ошибок, интеграции с уведомлениями, усиленной антиспам-защиты при атаках, защищённого управления сроками хранения и удалением обращений.

## Хостинг в России

Для российских персональных данных первичная запись/систематизация должны соответствовать применимым требованиям закона № 152-ФЗ, прежде всего ст. 18 ч. 5. Перед продакшеном требуется юридическая проверка актуальных обязанностей оператора (включая уведомление Роскомнадзора, политику, согласие, договоры с обработчиками, доступы и хранение).

Возможный поставщик: Beget Free (поддерживает PHP и MySQL по официальной странице бесплатного тарифа: https://beget.com/ru/hosting/free), но условия бесплатного хостинга запрещают `mail()` и любые исходящие письма, имеют лимит на ресурсы; реальную доступность PHP 8.2+, `mbstring`, `pdo_mysql`, HTTPS, домена и разрешённость коммерческой эксплуатации нужно подтвердить до размещения. https://beget.com/ru/rulesfree

Отправка персональных данных через зарубежный Cloudflare Worker или Telegram **не включена** из-за правовых и архитектурных рисков. Сначала хранение в РФ, потом отдельная проверка законности дополнительных каналов.

## Настройка и развёртывание

0. Не публиковать конфигурацию и записи пользователей в GitHub.
1. На российском PHP-хостинге настроить отдельный поддомен HTTPS для приёма данных и закрытое хранилище MySQL.
2. Выполнить один раз `lead_schema.sql` в базе данных.
3. Загрузить `lead-api.php` и `leads-admin.html` на этот хост в одну папку.
4. Настроить **серверные переменные окружения**, не включать секреты в публичный HTML/JS/GitHub:

```
MAESTRO_ALLOWED_ORIGIN=https://m72692591-collab.github.io
MAESTRO_DB_DSN=mysql:host=localhost;dbname=YOUR_DB;charset=utf8mb4
MAESTRO_DB_USER=YOUR_USER
MAESTRO_DB_PASSWORD=SECRET
MAESTRO_ADMIN_TOKEN=RANDOM_UNGUESSABLE_64_OR_MORE_CHARS
MAESTRO_IP_PEPPER=ANOTHER_RANDOM_SECRET_64_OR_MORE_CHARS
```

ПРИМЕЧАНИЕ: способ установки переменных зависит от платформы (на бесплатном виртуальном хостинге поддержка окружения может отличаться). Если безопасно задать их нельзя, **не развёртывать** эту версию — потребуется адаптер к закрытому конфигурационному файлу вне корня сайта и отдельный тест.

5. Выполнить серверный тест POST с корректной формой и заголовком Origin, убедиться в HTTP 201 и реально появившейся записи в БД.
6. Проверить GET `lead-api.php` с секретом администратора (без него должен возвращать 401), а также доступ с `leads-admin.html`.
7. После подтверждения российских требований по обработке ПД и теста подставить HTTPS адрес приёмника в метатег `maestro-lead-endpoint` на главной странице.
8. Провести тест из реального браузера Android и ПК. Не объявлять, что форма доставляет заявки, до подтверждения получения и резервного сценария.
9. Настроить резервное копирование/сроки хранения и процедуру удаления данных; проверить страницу политики ПД и отдельное согласие.

## Известные технические ограничения

- Ограничение скорости по IP в SQL — только базовый барьер; спам-защита на уровне WAF/CAPTCHA и продуманное ограничение на сеть при атаке нужны дополнительно.
- API не пытается отправлять уведомления с бесплатного Beget, так как это запрещено условиями. Заявки видны в кабинете владельца.
- Данные не передаются в Telegram, Gmail, GitHub, сторонние LLM или веб-аналитику.
- Админ-страница должна размещаться вместе с API на отдельном российском хосте и доступна через HTTPS. Для рабочей CRM понадобятся ролевая авторизация, аудирование доступа, резервное копирование и удаление по запросу.
- Серверный PHP **ещё не прогонялся на реальном хостинге**. Синтаксис и базовые тесты можно проверять в CI; нагрузочные и e2e-тесты — после настройки среды.

## Критерий готовности

«Заявки реально поступают» только если проверенный запрос от посетителя выдаёт HTTP 201, обращение появляется в российской БД, читается в закрытом кабинете владельца и пользователь видит номер обращения. Пока это не проверено — **система не запущена**.
