# Веб-канал существующего бота Amvera

## Подтверждено и не подтверждено
Владелец сообщил о работающем боте на Amvera. Точное название приложения, его URL, репозиторий и поддерживаемый API в доступных источниках пока не определены. Поиск по GitHub дал неполный результат, поэтому отсутствие кода не доказано. Не считать интеграцию действующей. Ни webhook, ни переменные, ни тариф Amvera не изменялись.

`site_channel.py` — написанный адаптер общей логики для Python-бота, не новый работающий сервер. Его функция `dispatch` принимает существующий обработчик как зависимость. `tests/test_site_channel.py` проверяет ограничения входа, изоляцию сессий и фильтрацию действий на учебном обработчике.

## Архитектура
Сайт → защищённый веб-маршрут существующего приложения → site_channel → общая бизнес-логика бота. Telegram/MAX/Avito остаются отдельными транспортами. Веб-сеансы получают префикс `web:` и не должны смешиваться с чатами мессенджеров. Проект `maestro` назначается сервером, не выбирается посетителем.

## Что подключить после нахождения приложения
1. Получить название/ссылку проекта, стек, текущий репозиторий, наличие HTTP-сервера, PORT, доступную память и действующий тариф. Секреты не пересылать в чат или GitHub.
2. Сделать резервную копию конфигурации; не менять существующие webhook и polling до теста.
3. Добавить HTTP-маршрут `/api/site/chat` в уже используемый сервер приложения. Не запускать второй цикл получения Telegram-сообщений.
4. До вызова адаптера проверить HTTPS, допустимый Origin/CSRF-политику, подписанную сессию, лимит размера тела, частоту, число одновременных запросов и суточный бюджет ИИ.
5. Из cookie/серверного хранилища извлечь подтверждённый session UUID, не брать его из произвольного JSON клиента. Передать его как `verified_session_id`.
6. Передать в `dispatch` существующий обработчик ответов. Он получает только разрешённый веб-контекст, а не полномочия администратора/Avito.
7. Выдавать только текст и проверенные команды навигации. Оформление обращения — отдельное действие с согласием, идемпотентным ключом и подтверждением записи в БД.
8. В рабочем окружении протестировать сессию A против B, отказ модели, повтор запроса, микрофон, приватность логов и предел бюджета. Только затем указать URL на сайте.

## Пример контракта
Запрос: `{ "request_id": "UUID", "text": "Нужен бот для сайта" }`.
Ответ: `{ "ok": true, "request_id": "UUID", "text": "Уточните задачу...", "actions": [{"type":"navigate","page":"brief-builder.html"}] }`.
Произвольные URL, исполнение JavaScript, изменение ставок/цен и прямые операции Avito не допускаются. Поле `received` не формируется языковой моделью — подтверждение получения заявки даёт сервер хранения.

## Критерий интеграции
Не «адаптер существует», а контрольный запрос с сайта реально обработан нужным приложением Amvera, сессии изолированы, бот в остальных каналах работает как прежде и расход укладывается в заданный лимит. Сейчас этот критерий ещё не пройден.
